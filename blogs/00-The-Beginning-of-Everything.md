# The Beginning of Everything

---

## Why Am I Doing This

Let me be honest: when I'm writing this, there's nothing in this repo except a lonely `README.md`.

But I'm starting anyway.

AI is everywhere right now. Every day I scroll through Twitter and Reddit, and I see mind-blowing demos — someone built a SaaS in three days with AI, another person is making five figures a month from AI-generated code, and someone even wrote an entire book using AI. The more I see, the more restless I get. I keep thinking: **I want to build an AI app too!**

The problem is... what do I actually know?

Some Python — enough to run a script. Frontend? Zero knowledge. React, Next.js, Tailwind CSS — might as well be hieroglyphics. Deployment? What's Vercel? Never heard of it.

But after hours of researching online, I came across an idea that really resonated with me:

> **In the AI era, the best way to learn is to just start building. Learn as you go, and pick up whatever skills you need along the way.**

Alright. That's the plan. I don't know if I can do it, but I'm going to try. Without action, everything else is just talk.

---

## Tech Stack Decision

After some research (okay, a lot of frantic Googling + asking ChatGPT + watching YouTube), I settled on this stack:

| Layer | Choice | Why |
|-------|--------|-----|
| **Frontend** | Next.js (React) | Massive community, rich ecosystem, endless resources |
| **Backend** | FastAPI (Python) | Easy to pick up, good performance, and at least I'm somewhat familiar with Python |
| **Deployment** | Vercel | Built by the same people as Next.js, supposedly the smoothest deployment experience out there |

There were plenty of alternatives — go full Node.js, use Django, go serverless... but I chose this combination for one key reason: **balance**.

1. **Simple enough**: I'm starting from zero. If the stack is too complex, I'll give up on day one. Can't have that.
2. **Powerful enough**: This isn't some toy framework. If I wanted to build a mature, even enterprise-grade app, this stack can handle it.
3. **Modern enough**: These technologies are all on the rise, with active communities. They won't be obsolete by the time I learn them.

Basically, I needed a path — one that's not too hard to walk, but can take me far. This stack is that path.

This might sound funny: **I don't know exactly what I'm building yet.**

Yep, you read that right. All I know is "I want to build an AI app." What form will it take? What problem will it solve? Who's the target user? No clue.

But I think that's fine.

## The Build-in-Public Philosophy

I've decided to document this project using the **Build in Public** approach.

What does that mean? Every step I take, every thing I learn, I'll cut a new branch and write a log in this `docs/` directory, recording:

- What I did
- What I learned
- What mistakes I made
- What thoughts I had

This approach has several benefits:

First, **it forces me to articulate what I'm learning**. Knowledge that isn't written down gets forgotten in days. Writing these logs is like doing a personal retrospective — it solidifies the learning.

Second, **it creates a record**. When this project is done (or abandoned), I can look back at these logs and probably find them pretty interesting. Like a developer's ship log.

Third, **it might help someone else**. If there's someone out there like me — wanting to build an AI app from scratch but not knowing where to start — these records could be a real, practical reference.
