# If You're Going to Learn, Learn the Best

---

## The Temptation of the Easy Path

Python 的 Hello World 嘛，对我来说不算新鲜事。

以前也写过 Python，`conda create -n myenv python=3.10`，然后 `pip install` 一通梭，能跑就行。这套流程闭着眼睛都能搞。如果我只是想"让项目赶紧跑起来"，五分钟就能搞定，然后开开心心地进入下一步。

但是这次，我在键盘上敲下 `conda` 的第一个字母的时候，突然停住了。

等一下。

我不是说好了要从头开始吗？我不是说好了要学新东西吗？如果我还在用三年前的那套工具链，那我到底是在"学新东西"，还是在"用旧习惯假装学新东西"？

这个念头一旦冒出来，就再也按不回去了。

---

## Asking the Right Question

于是我做了一件事，一件在以前的我看来可能有点"多此一举"的事——我没有直接动手，而是先去问了 AI 一个问题：

> **在 AI 领域里做 Python 开发的那些最厉害的人，他们现在用什么工具？**

注意，我问的不是"Python 环境管理用什么比较方便"，也不是"conda 和 venv 哪个好"。我问的是：**最厉害的人用什么。**

这个问题的措辞很重要。因为"方便"和"最好"往往不是同一个东西。方便的工具能让你快速开始，但最好的工具能让你走得最远。

AI 给了我一个答案：**mise-en-place + uv**。

说实话，这俩名字我一个都没听过。

---

## Down the Rabbit Hole

接下来就是漫长的调研时间。我没有立刻上手装，而是先搞明白：这些东西到底是什么？它们跟我知道的那些工具有什么区别？为什么它们会被认为是"最好的"？

先说大家比较熟悉的那条进化链：

**pip → virtualenv → conda → Poetry → uv**

大部分教程、大部分课程，教到 Poetry 或者 uv 就算到头了。知道 uv 的人已经算是走在前面了——它是 Rust 写的，速度飞快，把 pip、virtualenv、pyenv 这些工具的活儿全干了，而且干得更好。很多人到这一步就觉得够了。

但我又多挖了一层。

然后我发现了 **mise-en-place**（简称 mise）。

---

## The Manager of Managers

mise 是什么？一句话说：**它是管理 uv 的那个东西。**

如果说 uv 是一个超级厉害的 Python 工具链管理器，那 mise 就是站在 uv 背后的那个更高维度的存在。它不只管 Python，它管一切——Node.js、Go、Rust、Java、Terraform……任何你开发中需要的 runtime 和 CLI 工具，mise 都能管。

这听起来好像只是"又多了一层抽象"，但当我真正去理解它的设计理念后，我被说服了。

mise 的核心哲学是这样的：

**同样的工具，在你的电脑上只安装一次。**

想想看：如果你有 10 个 Python 项目，5 个用 Python 3.11，5 个用 Python 3.12。在传统方案里，每个项目各搞一套虚拟环境，磁盘上会有大量重复的东西。而 mise 的方式是——Python 3.11 只在你的系统里存一份，Python 3.12 也只存一份，然后通过配置文件精确地告诉每个项目该用哪个版本。

当你只有两三个项目的时候，这个差别不明显。但如果你有 100 个项目呢？

从数学上想一想，这其实是一个复杂度的问题。传统方案是 O(n) 的——项目越多，冗余越多，管理成本线性增长。而 mise 的方案趋近于 O(1)——不管你有多少项目，每个工具只装一次，管理成本几乎恒定。

**这不就是从本质上的最优解吗？**

---

## Why This Matters

有人可能会说：你一个刚开始的项目，就一个 repo，想那么远干嘛？先跑起来不就行了？

确实，对于"让这个项目跑起来"这个目标来说，用 conda 还是用 mise + uv，结果没有任何区别。都能跑。

但我在想的不是"这个项目"，我在想的是"从今天开始往后"。

如果我今天用 conda 搭好了环境，开心了五分钟，然后一个月后发现 mise + uv 才是更好的方案，到时候再迁移？那才叫折腾。

不如一开始就花点时间，把路选对。

而且更重要的是，我发现 **选工具的过程本身就是一种学习**。在调研 mise 和 uv 的过程中，我搞明白了很多以前模模糊糊的概念：

- 什么是 runtime version management
- Python 的包管理为什么这么混乱（历史债太重了）
- lockfile 的意义是什么
- 为什么现代工具链都在往 Rust 转
- "约定大于配置"到底是什么意思

这些知识不会因为工具更新换代而过时。就算明天出了一个比 mise 更好的东西，这些底层的理解都是通用的。

## Setting It Up

最后说下具体操作（虽然这篇重点不是教程）：

```bash
# 安装 mise
curl https://mise.run | sh

# 用 mise 安装 uv
mise use -g uv@latest

# 用 uv 创建项目
uv init my-ai-app
cd my-ai-app

# 跑一下 Hello World
uv run python -c "print('Hello, AI World!')"
```

就这么几行，干干净净，清清爽爽。

没有 conda 那一大坨环境，没有 `requirements.txt` 和 `setup.py` 的纠结，没有"到底用 pip 还是 pip3"的灵魂拷问。

`Hello, AI World!` 出现在终端里的那一刻，我知道这条路选对了。

---

## Reflection

回头看这次选择，我觉得最大的收获不是学会了 mise 和 uv 的用法——那些东西看文档就行了。

最大的收获是我意识到了一个道理：

**当你站在起点的时候，选择用什么工具出发，比急着迈出第一步更重要。**

不是说要无限拖延、追求完美。而是说，在动手之前多花一点时间去调研、去比较、去理解，这个时间投入的回报率是最高的。因为起点的选择会影响之后每一步的效率。

好的工具不会让你变厉害，但它会让你把时间花在真正重要的事情上。

而且说句大实话——用最先进的工具链，写代码的时候心情都更好。这个很重要。😄
