# Before You Run, Learn How to Not Fall

---

## The Urge to Keep Going

Python 的 Hello World 跑通了。`uv run python -c "print('Hello, AI World!')"` 在终端里乖乖吐出了那行字。

按照正常剧本，下一步应该是：开始写功能！加个 API！连个数据库！搞点 AI 的东西进去！

我确实很想这么干。那种"项目终于动起来了"的兴奋感让人特别想一路往前冲。

但我没有。

我停下来想了一个问题：**这个项目，我打算做很久。那我靠什么保证它不会在第三周就变成一坨屎山？**

---

## The Long Game Problem

这个问题看起来好像杞人忧天——你代码才几行啊，就开始担心屎山？

但我仔细想了想，觉得恰恰是现在最该想这件事。

打个比方：你要跑一场马拉松。起跑的时候你觉得浑身是劲儿，步子越迈越大，配速越拉越快。但如果你前 5 公里不看配速表、不控制节奏，后面 37 公里大概率会崩掉。

有经验的跑者是怎么做的？**他们每公里——甚至每几百米——就看一次手表。** 不是因为他们不自信，而是因为他们知道：跑长距离，靠的不是一腔热血，靠的是持续的、高频率的自我校准。

写代码也是一样的。

如果我写了 500 行代码才发现某个地方逻辑不对，那我可能得翻半天才能找到问题。但如果我每写 10 行代码就有一个机制告诉我"这 10 行是对的"，那 bug 根本就跑不远。

这个"机制"，就是 **TDD（Test-Driven Development）**。

---

## What TDD Really Is

TDD 的操作流程大家可能都听过：先写测试，再写代码，跑测试，重构，循环。红灯 → 绿灯 → 重构。

但我觉得如果只理解到这一层，那就只是学了个皮毛。

在调研 TDD 的过程中，我一直在想一个问题：**TDD 为什么有效？它到底在解决什么问题？**

想了挺久，我的理解是这样的：

TDD 的本质不是"测试"，而是**反馈循环（Feedback Loop）**。而且是一个极短的反馈循环。

你改了一行代码，跑一下测试，零点几秒就知道改对了没有。这个从"行动"到"得到结果"的延迟，被压缩到了几乎为零。

为什么这很重要？

因为**人类对一件事情的坚持程度，跟反馈速度直接相关**。

打游戏为什么让人上瘾？因为你每一个操作都有即时反馈——砍一刀有伤害数字，开一枪有命中音效。你不需要打完整个游戏才知道自己打得好不好。

健身为什么容易放弃？因为反馈太慢了——你今天做了 100 个俯卧撑，照镜子一看，跟昨天没任何区别。要坚持三个月才能看到变化。

写代码如果没有测试，就像健身——你写了一下午，run 一下，报了一个莫名其妙的错，根本不知道是哪里出了问题。这种体验是非常打击积极性的。

而 TDD 把写代码变成了打游戏——你每一次小改动，都有一个红灯或绿灯告诉你：对了，继续！或者，这里不对，再想想。

**快速反馈 = 快速修正 = 持续信心 = 能走得更远。**

这才是 TDD 真正在干的事。

## Why Now, Not Later

但问题来了：我这项目现在就一个 Hello World，有什么好测的？

确实，现在写测试的"实际价值"趋近于零。一个 `print("Hello, AI World!")` 你测它干嘛？

但我还是决定现在就把测试的基础设施搭好。原因有两个：

**第一，习惯要在最轻松的时候养成。**

现在项目简单，搭测试框架只需要几分钟。等到项目复杂了、代码多了再回头补？那就变成了"先还技术债"，那种痛苦程度完全不一样。就像整理房间——东西少的时候收拾一下很轻松，东西堆满了再收拾就想死。

**第二，基础设施要在第一天就存在。**

如果测试框架从项目第一天就在那里，那"写测试"就是开发流程的一部分，跟"写代码"一样自然。但如果项目做了一个月才加测试，那它在心理上就会变成一个"额外的负担"，一个"应该做但总想偷懒跳过"的东西。

这就像刷牙——从小就养成的习惯，你根本不会觉得它是负担。但如果有人 25 岁才开始刷牙……嗯，那估计每次都得跟自己做心理斗争。

## Setting Up the Foundation

所以我做了这些事：

```bash
# 在 pyproject.toml 里加上 pytest
uv add --dev pytest

# 创建测试目录
mkdir tests
touch tests/__init__.py

# 写第一个测试（虽然现在它测的东西很蠢）
```

```python
# tests/test_hello.py
def test_hello():
    assert 1 + 1 == 2  # 是的，就这么蠢，但绿灯亮了
```

```bash
# 跑一下
uv run pytest

# ✅ 1 passed in 0.01s
```

零点零一秒。一个绿色的 passed。

就是这么个蠢测试，看到那个绿色的一瞬间，我竟然有一种奇妙的安心感。

就好像——哦，这个项目里有一个守卫了。虽然它现在什么都守不住，但它在那儿了。以后每加一个功能，我都会给它加一把锁。等到有一天这个项目变得很复杂的时候，这些锁会是我最大的底气。

## Reflection

有一种事情，在当下做的时候看起来完全没必要，但从长远看它的回报率高得吓人。搭测试框架就是这种事情。

不是所有重要的事情都是紧急的。

很多人（包括以前的我）总是被紧急的事情推着走：赶紧加功能、赶紧出 demo、赶紧让它能用。而那些"重要但不紧急"的事情——比如写测试、写文档、想清楚架构——一推再推，最后就永远不做了。

这次我决定反过来。在还不紧急的时候，把重要的事情先做了。

一个只有 Hello World 的项目就配好了完整的测试框架，这看起来有点滑稽。但我赌这个决定在一个月后、三个月后、半年后会被证明是对的。

**做长期有价值的事情，从来都不会太早。**
