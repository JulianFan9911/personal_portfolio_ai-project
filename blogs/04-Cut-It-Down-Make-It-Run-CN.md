# Cut It Down, Make It Run

---

## Hitting the Wall

信心满满地打开了 Next.js 的官网。

毕竟 Node.js 和 pnpm 都装好了嘛，上一篇还在感慨"弹药备齐"。我心想，初始化一个 Next.js 项目应该跟 `uv init` 差不多吧？几行命令，搞定收工。

然后我点进了官方教程里那个"真实项目"的示例。

文件列表一拉出来，我人就傻了。

几十个文件。`middleware.ts`、`next.config.mjs`、`tailwind.config.ts`、各种 `layout.tsx`、`loading.tsx`、`error.tsx`……每一个文件名我都认识那些英文单词，但组合在一起完全不知道在干嘛。

那种感觉就像——你刚学会 26 个字母，然后有人把一本英文原版小说拍在你面前说"来，读吧"。

---

## Two Roads

接下来我大概纠结了十分钟。脑子里有两条路在打架：

**路 A：退回去学基础。** 从 React 是什么开始看起，把 Next.js 的文档过一遍，搞懂每个概念，然后再动手。这条路很稳，很安全，很"正确"。但问题是——我不知道要学多久才算"准备好了"。一周？一个月？而且说句实话，脱离项目纯学概念，我大概率坚持不了三天就会去刷手机。

**路 B：管它的，先干。** 不是无脑干，而是从那个"看不懂的复杂项目"里，砍出一个我能理解的最小版本，让它跑起来。先不管那几十个文件是干嘛的，我只要搞清楚：**这个项目"活着"最少需要什么？**

我选了 B。

不是因为我勇敢，是因为我知道，如果我现在选了 A，这个项目大概率会变成又一个"学了一半就吃灰"的 side project。

---

## Surgery

接下来的过程有点像做手术。

我打开那个官方示例的源码，在 AI 的帮助下，一个文件一个文件地读。不求全懂，只问一个问题：**这个文件删了，项目还能跑吗？**

能跑？砍掉。

不能跑？留下。

不确定？先砍掉，跑一下看报不报错。报错就加回来，不报错就说明它确实不是必需的。

一轮砍下来，几十个文件变成了这些：

```
my-ai-app/
├── api/                  # FastAPI 后端
│   └── index.py          # 一个 endpoint，返回 {"message": "Hello World"}
├── app/                  # Next.js 前端
│   ├── layout.tsx        # 最外层的壳
│   └── page.tsx          # 首页，就一行字
├── pyproject.toml        # Python 的依赖管理
├── package.json          # Node.js 的依赖管理
└── .mise.toml            # mise 的任务配置
```

就这些。干干净净，每一个文件我都知道它在干嘛。

说实话，**砍掉什么比加上什么难多了**。因为"加"只需要复制粘贴，而"砍"需要你理解每个东西的角色——你得知道它是什么，才敢说它可以不要。这个过程反而倒逼我搞懂了很多东西：`layout.tsx` 是做什么的，`page.tsx` 和路由是什么关系，前后端是怎么连在一起的。

有意思的是，我是通过"删代码"学会的，而不是通过"读教程"。

---

## The Dev Loop

骨架有了，下一步是让它真的跑起来，而且要跑得"舒服"。

还记得第三篇讲的 TDD 和快速反馈循环吗？我想把同样的思路用在开发体验上。理想状态是：改一行代码 → 刷一下浏览器 → 立刻看到变化。中间的摩擦越少越好。

于是我在 `.mise.toml` 里配了两个任务：

```toml
[tasks.dev]
description = "启动前端和后端的开发服务器"
run = ["pnpm dev & uv run uvicorn api.index:app --reload"]

[tasks.kill]
description = "杀掉所有占用的本地端口"
run = ["lsof -ti:3000,8000 | xargs kill -9 2>/dev/null || true"]
```

工作流变成了：

```bash
mise run kill  # 先清理干净
mise run dev   # 一键启动前后端
```

浏览器打开 `localhost:3000`，页面出来了。点一下 API 的按钮，`{"message": "Hello World"}` 回来了。

改一行前端的文字，保存，浏览器自动刷新，新内容立刻出现。

改一下后端的返回值，保存，再请求一次，新数据立刻回来。

整个反馈循环大概在两三秒以内。又是那种"打游戏"的感觉——每一个操作都有即时回馈。

## Reflection

回头看这个过程，我觉得最关键的决定不是"选了什么技术"，而是**在完全看不懂的时候，选择了动手而不是退缩**。

但我想强调一点：这里的"动手"不是蛮干。

面对一个远超自己能力的复杂项目，真正有用的行动不是硬着头皮从第一行读到最后一行，也不是闭着眼睛 `npm install` 然后祈祷。而是问自己：

> **这个东西的最小可运行版本是什么？**

然后就奔着那个最小版本去。

砍到只剩骨架，让它跑起来。跑起来的那一刻，你就有了一个"活的"东西可以互动、可以实验、可以犯错。从那以后，每加回来一个文件、一个功能，都是你主动选择的，而不是被动接受的。

**你不需要理解一切才能开始。你只需要找到那个最小的起点，然后让行动本身告诉你下一步该做什么。**

那些被我砍掉的 `middleware.ts`、`loading.tsx`、`error.tsx`，以后肯定会一个个加回来。但到那时候，我是因为"需要它"才加的，不是因为"教程里有"才加的。这两者的理解深度，完全不一样。

## What's Next

前后端的最小骨架跑起来了。浏览器里能看到页面，API 能返回数据。

虽然它现在丑得像毛坯房，但——它是**我的**毛坯房。

接下来就该往里面填东西了。
