# From Localhost to the World

---

## The Half-Finished State

本地 `mise run dev` 跑通了，前后端都能互相调用，测试也绿了。

按理说应该挺有成就感的。但说实话，这个状态离"能用"还差得远——代码只存在于我的电脑上，全世界只有我一个人能访问 `localhost:3000`。关掉终端，一切消失。

这让我想起第一篇博客里写的那句话：**代码只有跑起来、被人使用，才有价值。**

当时写这句话的时候，我以为"跑起来"就是 `mise run dev` 能启动。现在才发现，那只是最低标准。真正的"跑起来"，是部署到云端，让任何人、任何时间、任何地点都能访问。

---

## Deployment Used to Be Hard

部署这件事，以前我一直觉得很复杂。

买服务器、配域名、搞 SSL 证书、折腾 Nginx、设置防火墙、配置环境变量、处理进程守护... 光是列出来就头大。我见过不少人的 side project 死在这一步——代码写完了，但部署太麻烦，就一直躺在本地吃灰。

但 Vercel 把这些全包了。

它的逻辑很简单：你把代码放 GitHub，它帮你变成一个活着的网站。连接账号，选择 repo，点一下 Deploy，剩下的它自己搞定。不需要买服务器，不需要配 Nginx，甚至不需要手动触发——每次 push 代码，它自动重新部署。

这就是为什么我第一篇就选了 Vercel：**它把部署的门槛降到了几乎为零。**

---

## The Three-Minute Wait

点下 Deploy 按钮之后，页面开始滚动 build log。

说不紧张是假的。虽然本地跑得好好的，但谁知道云端会不会出什么幺蛾子？环境不一样、依赖版本不一样、配置不一样... 任何一个小问题都可能让 build 失败。

log 一行一行往下跑。Installing dependencies... Building application... Generating static pages...

三分钟后，状态变成了绿色的 **Ready**。

我点开那个 `.vercel.app` 的链接。页面加载出来了——不是 `localhost:3000`，是一个真实的、有域名的、任何人都能访问的 URL。

掏出手机，断开 WiFi，用 4G 打开同一个链接。

页面照样出来了。

---

## What "Deliver" Really Means

这时候我才真正理解了一件事。

之前不管代码写得多漂亮、架构设计得多优雅、测试覆盖得多全面，只要它还躺在本地，就只是个半成品。**写完代码不叫 Deliver，让别人能用才叫 Deliver。**

这也是 Build in Public 这个理念真正落地的时刻。

第一篇博客里我说要"边做边学，把过程公开出来"。但那时候 repo 里只有文档，没有能跑的东西。现在不一样了——有一个真实的 URL，任何人点进去都能看到我做的东西。不管它现在有多简陋，至少它是活的。

从"我在学"到"我在做"，再到"我做的东西别人能用"——这是三个完全不同的阶段。部署是从第二阶段跨到第三阶段的那道门。

---

## The Feedback Loop Closes

还有一个意外收获：部署之后，整个开发的反馈循环变得更完整了。

以前的循环是：改代码 → 本地测试 → 看效果。

现在的循环是：改代码 → push → Vercel 自动部署 → 在真实环境看效果。

这意味着我可以随时验证"这个改动在生产环境能不能跑"。不用等到最后一刻才发现问题，而是每一步都在真实环境里验证。这就是 CI/CD 的价值——它把"部署"从一个大事件变成了一个日常操作。

改一行代码，push，等两分钟，新版本就上线了。这种节奏感让开发变得更有掌控感。

---

## Reflection

回头看这五篇博客，有一条隐藏的线：

- 第一篇：决定开始，但什么都没有
- 第二篇：选工具，用最好的而不是最熟悉的
- 第三篇：搭测试，在只有 Hello World 的时候就建立反馈循环
- 第四篇：砍代码，从复杂项目里切出最小可运行骨架
- 第五篇：部署，让代码真正活在云端

这条线的本质是：**从想法到可交付成果的最短路径。**

不是先学完所有知识再动手，而是边做边学。不是先把功能做完美再部署，而是先让它上线再迭代。每一步都在缩短"想法"和"成果"之间的距离。

现在，这个项目终于有了一个任何人都能访问的 URL。它很简陋，只有一个 Hello World。但它是活的，它在云端，它是一个真正的起点。

---

## What's Next

部署成功只是开始。接下来要做的事情还有很多：

- 给这个骨架加上真正的功能
- 学习如何配置环境变量（真实应用必须的）
- 探索 Vercel 的 Analytics 和 Logs
- 也许，绑定一个自己的域名

但最重要的是：现在每写一行代码，我都知道它最终会跑在云端，被真实的用户看到。

这种感觉，和在本地自己玩，完全不一样。
