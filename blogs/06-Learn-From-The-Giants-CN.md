# Learn From The Giants

---

## Now What?

代码跑起来了。`mise run dev` 一敲，浏览器里出现了页面，点一下按钮，API 也能返回数据。

我盯着屏幕看了一会儿，心想：然后呢？

页面上有个导航栏，有个头像，有个 "About Me"，有个按钮。这些东西我都能看到，但它们是哪来的？哪个文件写的？怎么被加载到这个页面上的？

我完全不知道。

这感觉很奇怪——代码明明是我跑起来的，但我对它一无所知。就像你拿到了一辆车的钥匙，发动了引擎，却不知道方向盘在哪、油门在哪、怎么开出停车场。

---

## I Used to Read Code Like This

说实话，以前我看一个新项目，就是打开文件列表，从上往下一个个点开。

`layout.tsx`？点开，读一遍。看到一堆 `className` 和 `children`，好像懂了，又好像没懂。

`page.tsx`？点开，再读一遍。诶，这个 import 了那个，那个又 import 了另一个……

读到第五个文件的时候，前面四个已经混在一起了。我脑子里有一堆碎片，但拼不成完整的图。

最要命的是——我没法验证我理解得对不对。

我读了一段代码，觉得"这个组件大概是负责显示头像的"。但真的吗？我怎么确认？没有任何东西告诉我。只能继续往下猜。

这种学法就像闭着眼睛背地图。你可以背下"出门左转，走 100 米，再右转"，但你永远不知道这条路对不对，直到你真的走一遍撞了墙。

---

## Then I Learned Top-Down

这次练习教了我一个完全不同的方法。

不是从文件列表开始，而是从屏幕上看到的东西开始。

我看到导航栏里有个 "Home"。好，那我就搜 `"Home"`，看看这个字是在哪写的。

找到了——在 `Navigation.tsx` 里，有个数组，里面写着 `{ label: "Home", href: "/" }`。

然后我问自己：这个 `Navigation.tsx` 是怎么被加载到页面上的？

顺着 import 往上追，发现 `layout.tsx` 引用了它。再往上追，发现 `layout.tsx` 是整个 `(marketing)` 文件夹的布局。也就是说，只要访问这个文件夹下的任何页面，都会带上这个导航栏。

一路追下来，我突然明白了：原来 Next.js 的文件结构是这么工作的。

这个过程和以前最大的区别是什么？

**我每一步都能验证。**

我猜 "Home" 在 `Navigation.tsx` 里，搜一下，找到了，猜对了。我猜这个组件是被 `layout.tsx` 加载的，看一下 import，确实是，又对了。

每走一步都有反馈。对了就继续，错了就回头看。

这感觉完全不一样——不是在黑暗里摸索，而是每走一步脚下都有灯。

---

## The Moment That Blew My Mind

但最让我惊艳的，是我让 AI 帮我追一个功能的完整链路。

页面上有个按钮，写着 "Test API Hello Endpoint"。我好奇：点这个按钮，到底发生了什么？

以前我可能会这样做：先搜按钮的文字，找到代码，然后看 `onClick` 里写了什么，然后……然后就卡住了。因为里面调了一个函数，函数里又调了 `fetch`，fetch 请求了一个 `/api/hello`，但这个 API 是哪来的？Next.js 没有这个文件啊？

以前到这里我就放弃了。

但这次，我直接截了个图，圈出那个按钮，问 AI：这个按钮点下去发生了什么？整条链路是怎样的？

AI 给我讲得清清楚楚：

1. 点击触发 `handleApiCall` 函数
2. 函数里 `fetch("/api/hello")` 发请求
3. 这个请求被 `next.config.js` 里的 rewrite 规则拦截
4. 转发到 `http://127.0.0.1:8000/api/hello`——也就是 FastAPI 后端
5. FastAPI 在 `api/index.py` 里处理这个请求，返回 JSON

从前端按钮，到配置文件，到后端 Python，整条链路全通了。

我当时就觉得：好家伙，以前这种"反查"我根本做不到，不是因为方法不对，是因为中间会卡住。现在有了 AI，卡点全部被打通了。

---

## Why This Changes Everything

做完这个练习，我突然意识到一件事。

GitHub 上有那么多牛人的开源项目——Vercel 的源码、各种知名 AI 工具的代码。理论上，我可以从里面学到任何我想学的东西。

但以前我很少这么做。

为什么？因为一打开那些项目，几百个文件，我根本不知道从哪看起。README 写得再好，也只是告诉我"这个项目能干什么"，不会告诉我"这个功能是怎么实现的"。

然后我就退出去了，心想"等我基础打好了再来看"。

但"基础打好"是什么时候？不知道。于是这些牛人的代码就一直躺在那里，我一直没看。

现在我知道了：**不需要从头读到尾**。

正确的姿势是：先找到这个项目最核心的功能，把它跑起来，然后从 UI 反查——我看到了什么效果，它是怎么实现的。

目标不是全懂，是够我反查就够了。

我不需要理解那个项目的每一行代码。我只需要找到我关心的那部分，看懂它是怎么做的，然后把这个知识"偷"过来，用在自己的项目上。

这才是真正的"从牛人那里学习"。

---

## Reflection

回头看这次练习，最大的收获不是"我知道了 Hero.tsx 在哪"。

而是我学会了一种方法。

这种方法能用一辈子——不管以后遇到什么项目、什么框架、什么语言，只要我能把它跑起来，能看到屏幕上的东西，我就能用 Top-Down 的方式追溯到源代码。

而且不只是看代码。想想看：

- 学一个新产品？先用起来，遇到有意思的功能再研究它怎么做到的。
- 理解一个新业务？先看客户体验，再追溯背后的流程。
- 调试一个 bug？先看症状，再一路追到根因。

以前我总觉得，要学会一个东西，得先把所有基础知识补齐。现在我发现，更高效的路径是反过来的——先看到结果，再反推过程。因为有了结果作为锚点，我的学习是有方向的、有反馈的。

最好的学习，是看别人的项目。

而 Top-Down 加上 AI，让这件事终于变得可行。

---

## What's Next

现在我知道了屏幕上每个元素是哪个文件创建的。更重要的是，我知道了怎么在任何项目里找到这些信息。

接下来，是时候往这个骨架里填真正的内容了。

不过这次不一样。我不再是从零开始瞎摸索。我可以去找那些我欣赏的 portfolio 网站，用 Top-Down 的方法研究它们是怎么做的，然后把学到的东西搬到我自己的项目上。

站在巨人的肩膀上，看得更远。
